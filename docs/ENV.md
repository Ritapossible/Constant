# Settings checklist

Every variable and dashboard setting Constant needs, by where it's set. Values are secrets unless marked public. Never commit a value. `docs/GO-LIVE.md` says in which order to do them.

Status: ☐ to do · ☑ done (tick them in your own copy).

## Vercel: the web app (constant-units.vercel.app)

| ☐ | Variable | Needed for | Value |
|---|---|---|---|
| ☑ | `NEXT_PUBLIC_PRIVY_APP_ID` (public) | Sign-in | Privy dashboard → App settings → App ID |
| ☐ | `NEXT_PUBLIC_API_URL` (public) | Cable bills, naira account, receipts | `https://<constant-api>.onrender.com` |
| ☐ | `NEXT_PUBLIC_SPENDER_ADDRESS` (public) | "Pay from USDC" (hidden until set) | Same address as `SPENDER_ADDRESS` below |
| ☐ | `NEXT_PUBLIC_BASE_RPC_URL` (public, optional) | Balances on Base | A Base RPC URL (default: public) |
| ☐ | `NEXT_PUBLIC_ARC_RPC_URL` (public, optional) | Balances on Arc | Default `https://rpc.mainnet.arc.io` |
| ☐ | `NEXT_PUBLIC_ARC_AUTOPAY` (public) | "USDC on Arc" row under Pay from stablecoins | `true` only after the Arc go-live steps (GO-LIVE "USDC on Arc"); default off |
| ☐ | `NEXT_PUBLIC_SITE_URL` (public, optional) | Links and previews on a custom domain | `https://your-domain` |
| ☐ | `NEXT_PUBLIC_SMS_LOGIN` (public, optional) | Phone sign-in | Leave unset. Privy texts only US and Canada numbers on its standard plans; set `true` only after Privy's Scale plan with your own Twilio covers Nigeria and SMS is on in the Privy dashboard |
| ☐ | `NEXT_PUBLIC_CONTACT_EMAIL` (public, optional) | Footer, privacy page, FAQ, /llms.txt | Defaults to `constantunitshq@gmail.com`; set it only to change the address |

Redeploy after changing any `NEXT_PUBLIC_` value.

## Render: constant-api

|---|---|---|---|
| ☐ | `DATABASE_URL` | Everything | Set by the Blueprint from constant-db |
| ☐ | `REF_ENCRYPTION_KEY` | Decoder numbers at rest | `openssl rand -base64 32`; **same value on the worker**; keep a copy |
| ☐ | `REF_HMAC_KEY` | Decoder lookups | `openssl rand -base64 32`; **same on the worker** |
| ☐ | `PRIVY_APP_ID` | Sign-in check | Privy App ID |

| ☐ | `VTPASS_BASE_URL` | Decoder lookup | `https://sandbox.vtpass.com/api`, later `https://vtpass.com/api` |
| ☐ | `VTPASS_API_KEY`, `VTPASS_PUBLIC_KEY`, `VTPASS_SECRET_KEY` | Decoder lookup | VTpass → API Keys (secret shown once) |
| ☐ | `VTPASS_WEBHOOK_TOKEN` | VTpass callbacks | Generated by the Blueprint |
| ☐ | `PAYSTACK_SECRET_KEY` | Naira accounts, webhook signatures | Paystack → Settings → API Keys |
| ☐ | `PAYSTACK_PREFERRED_BANK` | Naira accounts | `test-bank` in test; `wema-bank` or `titan-paystack` live |
| ☐ | `CARD_TOPUPS` (optional) | Card, USSD and QR top-ups (D-075) | `true` to open them; off by default. Same Paystack key and webhook |
| ☐ | `TOPUP_CALLBACK_URL` (optional) | Where Paystack sends people back | Default: the first `WEB_ORIGINS` + `/app` |
| ☐ | `FUNDING_EMAIL_DOMAIN` (optional) | Phone-only users at Paystack | Default `users.constant.ng` |
| ☐ | `SPENDER_ADDRESS` | Dollar autopay (API never holds the key) | Address of the spender key below |
| ☐ | `BASE_RPC_URL` | Signature checks on Base | A paid Base RPC (Alchemy, QuickNode) |
| ☐ | `PAYCREST_BASE_URL` (optional) | Dollar rate | Default `https://api.paycrest.io` |
| ☐ | `OPS_TOKEN` | Operator API `/ops` (absent: no ops API) | `openssl rand -hex 32`; keep in a password manager, share only with operators |
| ☐ | `PAYCREST_API_KEY`, `PAYCREST_API_SECRET` | Off-ramp webhooks | Paycrest Sender Dashboard → API keys |
| ☐ | `ARC_AUTOPAY` | USDC on Arc (D-070) | `true` only after the Arc go-live steps; same value on the worker |
| ☐ | `ARC_RPC_URL` | Signature checks on Arc | Default `https://rpc.mainnet.arc.io` |

## Render: constant-worker

| ☐ | Variable | Needed for | Value |
|---|---|---|---|
| ☐ | `DATABASE_URL`, `REF_ENCRYPTION_KEY`, `REF_HMAC_KEY` | Everything | Same as the API |
| ☐ | `VENDING_PROVIDER` | Paying bills | `vtpass` |
| ☐ | `VTPASS_*` (4 values) | Paying bills, float check | Same as the API |
| ☐ | `VEND_FALLBACK_PHONE` | VTpass needs a phone | A Constant number |
| ☐ | `RESEND_API_KEY`, `EMAIL_FROM` | Email to users | Resend API key; `Constant <hello@your-domain>` |
| ☐ | `TERMII_API_KEY`, `TERMII_SENDER_ID` (optional) | SMS to users | Termii; sender ID `ConstUnits` (11 characters max) once approved |
| ☐ | `CHAINS` | Deposit indexing | `base,arc` |
| ☐ | `BASE_RPC_URL`, `ARC_RPC_URL` | Deposits, charges | Paid Base RPC; Arc default |
| ☐ | `DEPOSITS_ALL_TOKENS` (optional) | Warn about unsupported tokens | `true` only with a paid RPC |
| ☐ | `STELLAR_NETWORK`, `STELLAR_SECRET` | Public receipts | `testnet` + a Friendbot-funded secret; later `public` + ~5 XLM |
| ☐ | `SPENDER_PRIVATE_KEY` | Dollar autopay | A new key used for nothing else; ~$5 of ETH on Base for gas |
| ☐ | `TREASURY_ADDRESS` | Sweep of charged USDC (**required in production**) | A cold wallet or multisig on Base you control |
| ☐ | `CIRCLE_API_KEY` | Sanctions screening (**required in production** for dollar charges) | Circle Developer Console → API key with Compliance Engine |
| ☐ | `CIRCLE_SCREENING_CHAIN` (optional) | Screening | Default `ETH` (Circle lists no Base/Arc yet; EVM addresses are the same) |
| ☐ | `DOLLAR_DAILY_LIMIT_USD` (optional) | Cap on all dollar charges per 24 h | Default `500`; trips dollar charging off until a person resets it |
| ☐ | `FLOAT_MARGIN_NGN` (optional) | Naira kept at VTpass beyond each order | Default `50000` |
| ☐ | `SWEEP_MIN_USD` (optional) | Sweep threshold | Default `50` |
| ☐ | `BASE_CONFIRMATIONS` (optional) | Charge safety | Default `5` |
| ☐ | `OPS_EMAIL` | Alerts emailed to a person | Your ops inbox (needs `RESEND_API_KEY`) |
| ☐ | `PAYSTACK_SECRET_KEY`, `PAYSTACK_PREFERRED_BANK` | Withdrawals (still off until `payouts_enabled`) | Same as the API |
| ☐ | `PAYCREST_API_KEY`, `PAYCREST_API_SECRET` | Off-ramp: charged USDC → naira float | Paycrest Sender Dashboard |
| ☐ | `FLOAT_ACCOUNT_INSTITUTION`, `FLOAT_ACCOUNT_NUMBER`, `FLOAT_ACCOUNT_NAME` | Where the off-ramp pays naira | Your VTpass wallet funding account (VTpass dashboard → Fund wallet); institution is Paycrest's code for that bank (Paycrest "Code Standards") |
| ☐ | `FLOAT_LOW_NGN`, `FLOAT_TARGET_NGN` (optional) | When to refill and to how much | Defaults `200000` and `1000000` |
| ☐ | `OFFRAMP_MIN_USD` (optional) | Smallest off-ramp | Default `20` |
| ☐ | `ARC_AUTOPAY` | USDC on Arc: charges on Arc, transfer to Base (D-070) | `true` only after the Arc go-live steps; the worker refuses to start if Coinbase's manager isn't on Arc. The spender needs ~$2 of USDC **on Arc** for gas |
| ☐ | `ARC_BRIDGE_MIN_USD`, `ARC_BRIDGE_MAX_FEE_BPS` (optional) | Moving charged USDC from Arc to Base | Defaults `20` and `10` (0.1%; Circle charges 0 today) |

## Dashboards (not variables)

| ☐ | Where | Setting |
|---|---|---|
| ☑ | Privy → Allowed origins | `https://constant-units.vercel.app` |
| ☐ | Privy → Smart wallets | On; **Coinbase Smart Wallet**; network **Base** |
| ☐ | Privy → Smart wallets → gas sponsorship (paymaster) | On for Base, with the policy in GO-LIVE "Gas sponsorship policy" |
| ☐ | Privy → Smart wallets → networks → custom chain **Arc** (for USDC on Arc) | Chain ID `5042`, RPC `https://rpc.mainnet.arc.io`, bundler and paymaster URLs from Pimlico (`https://api.pimlico.io/v2/5042/rpc?apikey=…`). Confirm with Privy that Coinbase Smart Wallet works on a custom chain |
| ☐ | Pimlico (pimlico.io) | API key with Arc enabled; sponsorship policy as for Base |
| ☐ | VTpass → callback URL | `https://<constant-api>/webhooks/vtpass/<VTPASS_WEBHOOK_TOKEN>` |
| ☐ | Paystack → webhook URL | `https://<constant-api>/webhooks/paystack` |
| ☐ | Paystack → Dedicated Virtual Accounts | Ask Paystack to enable |
| ☐ | Paystack → Transfers | Turn **off** OTP for transfers (otherwise withdrawals go to a person); fund the Paystack balance |
| ☐ | Paycrest → Sender Dashboard → webhook URL | `https://<constant-api>/webhooks/paycrest` |
| ☐ | Ops switch | Withdrawals on only after Paystack's written OK (D-050): `POST /ops/flags/payouts_enabled` |
| ☐ | Database | Payments on: `UPDATE system_flags SET value = true … WHERE key = 'vending_enabled'` (GO-LIVE step 7) |
